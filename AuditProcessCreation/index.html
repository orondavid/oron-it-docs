    מדריך אבחון מסך שחור בחיבור TSplus / RDP

    מטרת המדריך

    מדריך זה נועד לאבחון מסך שחור בכניסה לשרת טרמינל דרך TSplus, כאשר הסשן מופיע כ־Active אך המשתמש רואה:

    • מסך שחור ריק
    • מסך שחור עם חלון תיקייה בלבד
    • שולחן עבודה ללא שורת משימות
    • מצב שבו explorer.exe אינו עולה אוטומטית

    המדריך מתאים לשרתי Terminal1 / Terminal2 בסביבת Windows Server עם TSplus.

    חשוב: את כל הבדיקות יש לבצע על שרת הטרמינל שבו המשתמש מחובר בפועל, ולא על שרת ה־DC או מאזן העומסים, אלא אם מצוין אחרת.

    1. פעולות ראשונות בזמן התקלה

    כאשר משתמש מדווח על מסך שחור:

    1. אין לבצע מיד Logoff.
    2. אין לבצע Restart לשרת.
    3. אין להפעיל מיד explorer.exe.
    4. קודם אוספים את הנתונים לפי הסדר הבא.

    2. זיהוי השרת והסשן

    הרץ על שרת הטרמינל:

    hostname
quser

    או למשתמש מסוים:

    quser EyalU

    יש לרשום:

    • שם המשתמש
    • Session ID
    • מצב הסשן
    • שעת ההתחברות
    • שם שרת הטרמינל

    דוגמה:

    USERNAME   SESSIONNAME   ID   STATE   IDLE TIME   LOGON TIME
EyalU      rdp-tcp#16   308   Active      .       12/07/2026 14:10

    מספרים כמו RDP-Tcp#16 הם שמות ערוץ RDP, לא Session ID.
    ה־Session ID הוא המספר בעמודת ID.

    3. בדיקת תהליכים בסשן

    החלף את המספר ב־Session ID הנכון:

    $SessionId = 308

Get-CimInstance Win32_Process |
Where-Object {
    $_.SessionId -eq $SessionId -and
    $_.Name -match 'explorer|dwm|ShellExperienceHost|StartMenuExperienceHost|userinit|logonsession|alternateshell|svcr|winxshell'
} |
Select-Object Name, ProcessId, SessionId, CreationDate, CommandLine |
Format-Table -AutoSize

    בדיקה ממוקדת ל־Explorer:

    Get-CimInstance Win32_Process |
Where-Object {
    $_.SessionId -eq $SessionId -and
    $_.Name -eq 'explorer.exe'
} |
Select-Object ProcessId, SessionId, CreationDate, CommandLine |
Format-List

    פירוש התוצאה

    מצב א': אין explorer.exe

    אם מופיעים רק:

    dwm.exe
svcr.exe

    אך אין explorer.exe, המשמעות היא שמעטפת Windows לא עלתה.

    מצב ב': קיים Explorer מסוג תיקייה בלבד

    explorer.exe /factory,{...} -Embedding

    זה אינו Explorer הראשי של שולחן העבודה. זה תהליך שנפתח להצגת חלון תיקייה בלבד.

    מצב ג': קיים Explorer רגיל

    C:\Windows\explorer.exe

    אם הוא קיים ועדיין יש מסך שחור, יש לבדוק אם הוא תקוע, אם DWM פעיל ואם יש שגיאת Shell או פרופיל.

    4. בדיקת כל תהליכי Explorer לפי משתמש

    Get-Process explorer -IncludeUserName

    בדיקה למשתמש מסוים:

    Get-Process explorer -IncludeUserName |
Where-Object { $_.UserName -eq 'UNITEDTOURS\EyalU' } |
Select-Object Id, UserName, StartTime, CPU, WorkingSet

    אם המשתמש אינו מופיע ברשימה, אין לו Explorer פעיל.

    5. איסוף לוגים של TSplus

    הלוגים נמצאים בדרך כלל תחת:

    C:\wsession\Trace\<UserName>

    לדוגמה:

    Get-ChildItem "C:\wsession\Trace\EyalU" -File -ErrorAction SilentlyContinue |
Sort-Object LastWriteTime -Descending |
Select-Object -First 10 LastWriteTime, Length, FullName

    יש לאסוף את שני הקבצים האחרונים מאותה שעת התחברות:

    trace_..._wsess.txt
trace_..._wsess_tsplserver.txt

    להצגת התוכן:

    $Files = Get-ChildItem "C:\wsession\Trace\EyalU" -File |
Where-Object { $_.LastWriteTime -ge (Get-Date).AddMinutes(-20) } |
Sort-Object LastWriteTime

foreach ($File in $Files) {
    Write-Host "`n===== $($File.FullName) =====" -ForegroundColor Cyan
    Get-Content $File.FullName
}

    שורות חשובות בלוג

    חפש:

    Mode Alternate Shell
RemoteDesktop: started as fallback application
Mode Desktop
Launching C:\WINDOWS\explorer.exe
ShellExecute returns
Exit 11

    פירוש

    אם TSplus רושם:

    Launching C:\WINDOWS\explorer.exe
ShellExecute returns : <number>

    אך אין explorer.exe בסשן, סביר שהתהליך נוצר ונסגר מיד, או שלא נשאר פעיל.

    השגיאה:

    Unable to open the Virtual Channel!

    עשויה להיות קשורה לערוץ מדפסת, Clipboard או Universal Printer. אם היא מופיעה גם אצל משתמשים תקינים, אין להסיק לבדה שהיא גורמת למסך השחור.

    6. בדיקת Registry של Shell ו־Userinit

    ברמת המערכת

    reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v Shell
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v Userinit

    מצב תקין:

    Shell       REG_SZ    explorer.exe
Userinit    REG_SZ    C:\Windows\system32\userinit.exe,C:\wsession\logonsession.exe

    ברמת המשתמש

    קבלת SID:

    $Profile = Get-CimInstance Win32_UserProfile |
Where-Object { $_.LocalPath -eq 'C:\Users\EyalU' }

$Sid = $Profile.SID

$Profile | Select-Object LocalPath, SID, Loaded, Status, LastUseTime
$Sid

    בדיקת Hive:

    Test-Path "Registry::HKEY_USERS\$Sid"

    בדיקת Winlogon של המשתמש:

    reg query "HKU\$Sid\Software\Microsoft\Windows NT\CurrentVersion\Winlogon"

    ערכים אפשריים:

    Shell = explorer.exe

    או:

    Shell = C:\ProgramData\alternateshell.exe

    alternateshell.exe הוא רכיב חתום של TSplus / Remote Access World. אין למחוק אותו אוטומטית בלי לבדוק אם המשתמש מוגדר בצורה שונה ב־TSplus.

    בדיקת חתימה:

    Get-AuthenticodeSignature "C:\ProgramData\alternateshell.exe" |
Select-Object Status, StatusMessage,
    @{N='Signer';E={$_.SignerCertificate.Subject}}

    7. השוואת Shell בין כל המשתמשים המחוברים

    Get-CimInstance Win32_UserProfile |
Where-Object { $_.Loaded -eq $true -and $_.SID -like 'S-1-5-21-*' } |
ForEach-Object {
    $Sid  = $_.SID
    $Path = "Registry::HKEY_USERS\$Sid\Software\Microsoft\Windows NT\CurrentVersion\Winlogon"

    $Shell = if (Test-Path $Path) {
        (Get-ItemProperty $Path -ErrorAction SilentlyContinue).Shell
    }

    [pscustomobject]@{
        UserProfile = Split-Path $_.LocalPath -Leaf
        SID         = $Sid
        Shell       = $Shell
    }
} | Format-Table -AutoSize

    אם רק משתמש אחד מוגדר עם alternateshell.exe, יש לבדוק אם מדובר בהגדרה ישנה או הקצאת אפליקציות ייחודית ב־TSplus.

    8. גיבוי ומחיקת Override אישי של Shell

    יש לבצע רק לאחר אימות שהמשתמש אמור לקבל Full Desktop רגיל כמו יתר המשתמשים.

    גיבוי

    New-Item -Path C:\Temp -ItemType Directory -Force

reg export "HKU\<SID>\Software\Microsoft\Windows NT\CurrentVersion\Winlogon" `
"C:\Temp\User-Winlogon-Backup.reg" /y

    מחיקת ערך Shell בלבד

    reg delete "HKU\<SID>\Software\Microsoft\Windows NT\CurrentVersion\Winlogon" `
/v Shell /f

    לא למחוק את כל המפתח.

    לאחר מכן:

    1. לבצע Logoff מלא.
    2. להתחבר מחדש.
    3. לוודא שה־Shell אינו נוצר מחדש.
    4. לבדוק שהשולחן עולה תקין.

    9. Audit Process Creation

    מטרת ה־Audit

    Audit Process Creation רושם Event ID 4688 בכל פעם שתהליך חדש נוצר.

    הוא מאפשר לבדוק:

    • האם explorer.exe נוצר בפועל
    • באיזו שעה
    • תחת איזה משתמש
    • מי היה ה־Parent Process
    • באיזו שורת פקודה הופעל

    בדיקת מצב

    הרץ על כל שרת טרמינל:

    auditpol /get /subcategory:"Process Creation"

    מצב פעיל:

    Process Creation    Success

    הפעלה

    auditpol /set /subcategory:"Process Creation" /success:enable /failure:disable

    הוספת Command Line לאירוע 4688

    New-ItemProperty `
-Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" `
-Name ProcessCreationIncludeCmdLine_Enabled `
-PropertyType DWord `
-Value 1 `
-Force

    אין צורך באתחול.

    10. איסוף Audit בזמן מסך שחור

    כל אירועי 4688 הרלוונטיים ב־20 הדקות האחרונות

    $User = 'EyalU'
$From = (Get-Date).AddMinutes(-20)

Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4688
    StartTime = $From
} -ErrorAction SilentlyContinue |
Where-Object {
    $_.Message -match "\\$User\b" -or
    $_.Message -match 'explorer\.exe|userinit\.exe|logonsession\.exe|alternateshell\.exe|svcr\.exe'
} |
Select-Object TimeCreated, Id, Message |
Format-List

    רק Explorer

    $From = (Get-Date).AddMinutes(-20)

Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4688
    StartTime = $From
} -ErrorAction SilentlyContinue |
Where-Object {
    $_.Message -match 'explorer\.exe'
} |
Select-Object TimeCreated, Message |
Format-List

    שמירה לקובץ

    $User = 'EyalU'
$TimeStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$OutFile = "C:\Temp\Audit-$User-$TimeStamp.txt"
$From = (Get-Date).AddMinutes(-20)

New-Item -Path C:\Temp -ItemType Directory -Force | Out-Null

Get-WinEvent -FilterHashtable @{
    LogName   = 'Security'
    Id        = 4688
    StartTime = $From
} -ErrorAction SilentlyContinue |
Where-Object {
    $_.Message -match "\\$User\b" -or
    $_.Message -match 'explorer\.exe|userinit\.exe|logonsession\.exe|alternateshell\.exe|svcr\.exe'
} |
Select-Object TimeCreated, Id, Message |
Format-List |
Out-File $OutFile -Encoding UTF8

$OutFile

    פירוש Audit

    קיים Event 4688 ל־Explorer אך אין Explorer פעיל

    Explorer נוצר ונסגר מיד.

    אין Event 4688 ל־Explorer

    Windows לא יצר בפועל את התהליך, למרות שלוג TSplus עשוי להציג Launching explorer.exe.

    Parent Process

    יש לבדוק אם ה־Parent הוא:

    C:\wsession\logonsession.exe

    או:

    C:\Windows\System32\userinit.exe

    12. הפעלת Explorer ידנית בסשן

    יש לבצע רק לאחר איסוף הלוגים.

    באמצעות PsExec

    PsExec חייב לרוץ על שרת הטרמינל שבו קיים הסשן.

    בדיקת שרת:

    hostname
quser

    הרצה:

    cd C:\PSTools
.\PsExec.exe -accepteula -i <SessionId> -d C:\Windows\explorer.exe

    לדוגמה:

    .\PsExec.exe -accepteula -i 308 -d C:\Windows\explorer.exe

    אם הפקודה רצה משרת אחר, יש לציין את שרת הטרמינל:

    .\PsExec.exe \\Terminal1 -accepteula -i 308 -d C:\Windows\explorer.exe

    או:

    .\PsExec.exe \\Terminal2 -accepteula -i 308 -d C:\Windows\explorer.exe

    לאחר ההפעלה:

    Get-CimInstance Win32_Process |
Where-Object {
    $_.SessionId -eq <SessionId> -and
    $_.Name -eq 'explorer.exe'
} |
Select-Object ProcessId, SessionId, CreationDate, CommandLine

    אם השולחן חוזר מיד, הסשן, DWM והחיבור תקינים, והכשל הוא בטעינת ה־Shell הראשונית.

    13. קריסות PrintIsolationHost

    בשרתים שבהם קיימות קריסות חוזרות של:

    PrintIsolationHost.exe

    יש לאסוף את האירועים המלאים:

    Get-WinEvent -FilterHashtable @{
    LogName      = 'Application'
    ProviderName = 'Application Error'
    Id           = 1000
    StartTime    = (Get-Date).AddDays(-7)
} |
Where-Object { $_.Message -match 'PrintIsolationHost.exe' } |
Select-Object -First 10 TimeCreated, Id, Message |
Format-List

    יש לחפש:

    • Faulting module name
    • Exception code
    • Fault offset
    • DLL או Driver Name

    קריסות הדפסה אינן הוכחה ישירה למסך שחור, אך הן עשויות להאט Logon או להפריע לערוצי TSplus.

    14. חבילת איסוף מומלצת לכל אירוע

    בכל מסך שחור יש לשמור:

    1. פלט quser
    2. שם השרת
    3. Session ID
    4. פלט התהליכים בסשן
    5. Get-Process explorer -IncludeUserName
    6. שני לוגי TSplus
    7. Audit Event 4688
    8. Event Viewer מה־20 דקות האחרונות
    9. Registry Shell ו־Userinit
    10. צילום מסך של מצב המשתמש ב־TSplus

    שם תיקייה מומלץ:

    C:\Temp\BlackScreen\<User>-<YYYYMMDD-HHMMSS>

    15. סקריפט איסוף מהיר

    הסקריפט הבא אוסף את הנתונים המרכזיים. יש לעדכן User ו־SessionId:

$SessionId = 308

$Base = "C:\Temp\BlackScreen\$User-$TimeStamp"
$From = (Get-Date).AddMinutes(-20)

New-Item -Path $Base -ItemType Directory -Force | Out-Null

hostname | Out-File "$Base\hostname.txt"
quser | Out-File "$Base\quser.txt"

Where-Object {

} |
Select-Object Name, ProcessId, SessionId, CreationDate, CommandLine |
Format-List |
Out-File "$Base\session-processes.txt"

Get-Process explorer -IncludeUserName -ErrorAction SilentlyContinue |
Select-Object Id, UserName, StartTime, CPU, WorkingSet |
Format-Table -AutoSize |
Out-File "$Base\all-explorer-processes.txt"

Get-WinEvent -FilterHashtable @{

    StartTime = $From
} -ErrorAction SilentlyContinue |
Where-Object {
    $_.Message -match "\\$User\b" -or

} |
Select-Object TimeCreated, Id, Message |
Format-List |
Out-File "$Base\audit-4688.txt" -Encoding UTF8

} |

    16. מה לא לעשות לפני איסוף

    אין לבצע לפני איסוף הנתונים:

    • Logoff למשתמש
    • סגירת הסשן
    • Restart לשרת
    • הפעלת Explorer ידנית
    • שינוי Registry
    • מחיקת פרופיל
    • הפעלת WinXshell
    • שינוי SetHook
    • הסרת רכיבים

    17. מסקנות אפשריות

    ממצא משמעות
    אין Explorer ואין Event 4688 Explorer לא נוצר בפועל
    יש Event 4688 אך אין Explorer Explorer נוצר ונסגר מיד
    יש Explorer /factory -Embedding בלבד נפתח חלון תיקייה, לא Desktop Shell
    Explorer ידני מחזיר את שולחן העבודה הבעיה היא בטעינת Shell הראשונית
    DWM אינו קיים חשד לבעיה גרפית או Session Desktop
    Shell אישי שונה מכל המשתמשים לבדוק Override או הגדרת TSplus חריגה
    TSplus מציג Launching Explorer אך אין Process לבדוק Audit, ProcDump או ProcMon
    PrintIsolationHost קורס שוב ושוב לבדוק Driver / Printer DLL / Universal Printer

    18. ProcDump – מתי להשתמש

    ProcDump נדרש רק אם:

    • Event 4688 מוכיח ש־Explorer נוצר
    • Explorer נעלם מיד
    • אין Event 1000 ברור
    • התקלה חוזרת

    ProcDump עצמו תופס מעט מאוד מקום. קובץ Dump נוצר רק בעת אירוע, וגודלו תלוי בסוג ה־Dump.

    בשלב ראשון ניתן להסתפק ב־Audit ובאיסוף הלוגים. אם הבעיה תחזור ונוכיח ש־Explorer נוצר ונסגר, ניתן לעבור ל־ProcDump או ProcMon.
