    שרת SFTP עם 2FA (Google Authenticator) + Chroot + Windows Share (CIFS) – Runbook

    מסמך תפעולי קצר וברור: נתיבים, פקודות, ניהול משתמשים, 2FA, Mountים ולוגים.

    ארכיטקטורה בקצרה

    • OpenSSH (SFTP)
    • Chroot לכל משתמש
    • Bind Mount לתיקיית משתמש בתוך ה־Share
    • CIFS Mount לשיתוף Windows (SMB)
    • Windows File Server

    נתיבים חשובים

    Chroot ונתיבי משתמש

    • /srv/sftp/chroot/{user} – תיקיית ה־chroot של המשתמש
    • /srv/sftp/chroot/{user}/uploads – תיקיית העלאות בתוך ה־chroot
    • /srv/sftp/chroot/{user}/.ga – תיקיית Google Authenticator
    • /srv/sftp/chroot/{user}/.ga/.google_authenticator – קובץ ה־secret של 2FA

    שיתוף Windows (CIFS) + Bind

    • /srv/sftp-windows – נקודת ה־mount הראשית של ה־Windows share
    • /srv/sftp-windows/{user} – תיקיית משתמש בתוך ה־Share (מקור ל־bind)

    קבצי קונפיגורציה

    • /etc/ssh/sshd_config – הגדרות SSH
    • /etc/pam.d/sshd – PAM עבור SSH/2FA
    • /etc/fstab – מיפויי mount קבועים (CIFS + bind)

    לוגים

    • /var/log/auth.log – לוג התחברויות SSH/2FA
    • dmesg – הודעות kernel (כולל CIFS)

    Mountים (CIFS + Bind)

    בדיקה מה מחובר

    mount | grep sftp

    תצוגה היררכית (מומלץ):

    findmnt | grep sftp

    טעינת mountים מה־fstab

    sudo mount -a

    בדיקה מפורטת עם פלט:

    sudo mount -av

    אחרי שינוי ב־fstab (חשוב)

    sudo systemctl daemon-reload
sudo mount -a

    חיפוש שורות רלוונטיות ב־fstab

    sudo grep -nE '\scifs\s|sftp-windows|/srv/sftp/chroot' /etc/fstab

    דוגמה למבנה מומלץ ב־fstab

    //fs01.meida.int/sftp-uploads /srv/sftp-windows cifs credentials=/etc/samba/sftp-credentials,vers=3.0,uid=0,gid=988,forceuid,forcegid,file_mode=0770,dir_mode=0770,nounix,serverino,noperm 0 0
/srv/sftp-windows/client1 /srv/sftp/chroot/client1/uploads none bind 0 0
/srv/sftp-windows/client2 /srv/sftp/chroot/client2/uploads none bind 0 0
/srv/sftp-windows/oron    /srv/sftp/chroot/oron/uploads    none bind 0 0

    ✅ בדיקה מהירה שה־bind באמת bind: בשורת mount על ה־uploads צריך להופיע type none (bind) ולא type cifs.

    ניהול משתמשים

    יצירת משתמש SFTP חדש (דרך הסקריפט)

    sudo ~/add-sftp-user.sh {user}

    מה הסקריפט צריך לעשות (במינימום):

    • ליצור משתמש
    • ליצור תיקיות: chroot, uploads, .ga
    • ליצור קובץ 2FA בנתיב:
    • /srv/sftp/chroot/{user}/.ga/.google_authenticator
    • הרשאות מומלצות:
    • תיקיית chroot בבעלות root:root
    • תיקיית .ga בבעלות המשתמש והרשאה 700
    • קובץ .google_authenticator הרשאה 600

    בדיקה מהירה:

    ls -la /srv/sftp/chroot/{user}
ls -la /srv/sftp/chroot/{user}/.ga

    מחיקת משתמש

    מחיקה (כולל home רגיל אם קיים):

    sudo userdel -r {user}

    מחיקת תיקיות SFTP (אם נדרש):

    sudo rm -rf /srv/sftp/chroot/{user}
sudo rm -rf /srv/sftp-windows/{user}

    ⚠️ מחיקה ב־/srv/sftp-windows/{user} תמחק גם מה־Windows share.

    2FA רק למשתמשי SFTP (קבוצת sftpusers)

    לראות מי בקבוצה

    getent group sftpusers

    בדיקת משתמש ספציפי:

    id {user}

    הוספה לקבוצה (יחייב 2FA)

    sudo usermod -aG sftpusers {user}

    הסרה מהקבוצה (יבטל 2FA)

    sudo gpasswd -d {user} sftpusers

    PAM – החלת 2FA רק על חברי sftpusers

    קובץ:

    • /etc/pam.d/sshd

    הבלוק המומלץ:

    # If NOT in sftpusers -> skip GA line
auth  [success=1 default=ignore] pam_succeed_if.so user notingroup sftpusers
auth  required  pam_google_authenticator.so secret=/srv/sftp/chroot/${USER}/.ga/.google_authenticator

    לאחר שינוי:

    sudo systemctl restart ssh

    לוגים ו־Troubleshooting

    צפייה חיה:

    sudo tail -f /var/log/auth.log

    חיפוש שגיאות נפוצות:

    sudo grep -E "sshd|pam_google_authenticator|Authentication failure|Invalid verification code|Permission denied" /var/log/auth.log

    שגיאות CIFS מהקרנל:

    sudo dmesg | grep -i cifs

    זמן מערכת (קריטי ל־TOTP)

    בדיקה:

    timedatectl

    הפעלת NTP:

    sudo timedatectl set-ntp true

    WinSCP – “Upload הצליח אבל Permission denied / מבקש סיסמה שוב”

    למה זה קורה?

    • העלאה רגילה: לרוב רק write → הצלחה.
    • יצירה/עריכה דרך WinSCP Editor: WinSCP מנסה גם:
    • chmod / SETSTAT (הרשאות)
    • timestamp
    • rename לקובץ זמני

    כאשר היעד הוא CIFS (Windows share), פעולות POSIX לא תמיד נתמכות → מתקבל Permission denied ואז WinSCP עלול להציג prompt נוסף.

    פתרון מומלץ בצד הקליינט (WinSCP)

    • Preferences → Transfer
    • בטל Preserve timestamp
    • Preferences → Transfer → Endurance
    • סמן Ignore permission errors

    פקודות בדיקה כלליות

    סטטוס SSH:

    sudo systemctl status ssh

    Restart:

    sudo systemctl restart ssh

    מי מחובר:

    w

    בדיקת פורט SSH מאזין:

    ss -tulpn | grep ssh

    הערה למראה RTL ב־MkDocs (חשוב)

    כדי שהתוכן יוצג יפה מימין לשמאל, מומלץ להוסיף extra_css עם קובץ RTL.

    דוגמה (mkdocs.yml):

    extra_css:
  - stylesheets/rtl.css

    ותוכן docs/stylesheets/rtl.css:

    html, body, .md-content { direction: rtl; }
.md-typeset code, .md-typeset pre { direction: ltr; }

    כך עברית תוצג RTL, אבל קוד יישאר LTR (קריא).
