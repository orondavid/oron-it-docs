    טופולוגיה

    [לקוח חיצוני]  --SFTP (מפתח + סיסמה + 2FA)-->  [שרת לינוקס: newsftp]
                                                          |
                                                    CIFS/SMB mount
                                                          |
                                                  [שרת Windows: fs01]
                                                  \\fs01\sftp-uploads
                                                     /        \
                                               /client1    /client2 ...
    • שרת לינוקס: Ubuntu Server 24.04 LTS על ESXi 8.0 U2
    • שרת Windows: שרת קבצים עם AD/DC בדומיין
    • אימות: מפתח SSH + סיסמה + Google Authenticator (2FA)
    • כל לקוח: תיקיית chroot עם uploads שממופה לתיקיה אישית בשרת Windows

    נתיבים חשובים בשרת הלינוקס

    נתיב תיאור
    /etc/ssh/sshd_config קובץ הגדרות SSH הראשי
    /etc/pam.d/sshd קובץ PAM לשירות SSH (סיסמה + 2FA)
    /etc/fstab הגדרות mount אוטומטיות באתחול
    /etc/samba/sftp-credentials פרטי חיבור לשרת Windows (username/password/domain)
    /srv/sftp-windows/ נקודת mount של שיתוף Windows (CIFS)
    /srv/sftp/chroot/ בסיס תיקיות chroot לכל משתמשי SFTP
    /srv/sftp/chroot/<user>/ תיקיית chroot של משתמש (root:root, 755)
    /srv/sftp/chroot/<user>/uploads/ תיקיית העלאות – ממופה (bind) לשרת Windows
    /srv/sftp/chroot/<user>/.google_authenticator קובץ סוד ה-2FA (PAM קורא מכאן)
    /srv/sftp/chroot/<user>/.ga/ תיקיית עבודה זמנית ל-google-authenticator
    /srv/sftp/chroot/<user>/.ssh/authorized_keys מפתחות SSH ציבוריים של המשתמש
    /srv/sftp-windows/<user>/ תיקיית המשתמש בשרת Windows (דרך ה-mount)
    /opt/sftp-admin/sftp_menu.sh תפריט ניהול (מיקום בשרת)
    /home/iteam/add-sftp-user.sh סקריפט הוספת משתמש (מיקום בשרת)
    /usr/local/bin/menu alias גלובלי לתפריט הניהול
    /var/log/auth.log לוג אימות SSH (לאבחון בעיות חיבור ו-2FA)

    פקודות התקנה ראשונית

    עדכון מערכת

    sudo apt update && sudo apt upgrade -y

    מעדכן את רשימת החבילות ומתקין עדכוני אבטחה.

    התקנת חבילות נדרשות

    sudo apt install -y openssh-server libpam-google-authenticator cifs-utils

    openssh-server – שרת SSH/SFTP.
    libpam-google-authenticator – מודול PAM לאימות 2FA.
    cifs-utils – כלים לחיבור שיתוף Windows (SMB/CIFS).

    פקודות הגדרת SSH ו-PAM

    גיבוי קובץ SSH לפני שינוי

    sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak

    יוצר גיבוי של קובץ ההגדרות לפני כל שינוי.

    הוספת הגדרות SFTP chroot ל-SSH

    sudo tee -a /etc/ssh/sshd_config << 'EOF'

# --- SFTP chroot for sftpusers ---
Match Group sftpusers
    ChrootDirectory /srv/sftp/chroot/%u
    ForceCommand internal-sftp
    AuthenticationMethods publickey,keyboard-interactive
    AllowTcpForwarding no
    X11Forwarding no
    PermitTTY no
EOF

    מוסיף לסוף הקובץ הגדרות chroot לקבוצת SFTP.
    ChrootDirectory – מגביל כל משתמש לתיקיה שלו בלבד.
    AuthenticationMethods – חייב מפתח SSH ואחר כך סיסמה + 2FA.

    הפעלת keyboard-interactive (נדרש ל-2FA)

    echo "KbdInteractiveAuthentication yes" | sudo tee -a /etc/ssh/sshd_config

    מאפשר אימות אינטראקטיבי (נדרש כדי שהשרת יבקש קוד 2FA).

    גיבוי PAM לפני שינוי

    sudo cp /etc/pam.d/sshd /etc/pam.d/sshd.bak

    גיבוי קובץ PAM של SSH.

    הוספת Google Authenticator ל-PAM

    sudo sed -i '/^@include common-auth$/a auth required pam_google_authenticator.so nullok' /etc/pam.d/sshd

    מוסיף שורת 2FA אחרי אימות הסיסמה.
    nullok – משתמש ללא קובץ .google_authenticator נכנס עם סיסמה בלבד (מאפשר הוספה הדרגתית).

    בדיקת תקינות הגדרות SSH

    sudo sshd -t

    בודק שאין שגיאות תחביר בקובץ ההגדרות. לרוץ לפני כל restart.

    הפעלה מחדש של SSH

    sudo systemctl restart ssh

    מפעיל מחדש את שירות ה-SSH. שינויים ב-sshd_config ו-PAM נכנסים לתוקף.

    פקודות חיבור שיתוף Windows

    יצירת קובץ credentials

    sudo nano /etc/samba/sftp-credentials

    עורך (יוצר) את קובץ פרטי ההתחברות לשרת Windows.
    תוכן הקובץ: 

    username=DOMAIN\username
password=YourPassword
domain=DOMAIN

    הגדרת הרשאות credentials (חובה)

    sudo chmod 600 /etc/samba/sftp-credentials

    מגביל קריאה לקובץ ה-credentials לבעלים בלבד. בלי זה mount עלול להיכשל.

    יצירת תיקיית mount

    sudo mkdir -p /srv/sftp-windows

    יוצר את תיקיית ה-mount שבה יופיע שיתוף Windows.

    חיבור שיתוף Windows ידנית

    sudo mount -t cifs //192.168.130.240/sftp-uploads /srv/sftp-windows \
  -o credentials=/etc/samba/sftp-credentials,uid=0,\
gid=$(getent group sftpusers | cut -d: -f3),file_mode=0770,dir_mode=0770,vers=3.0

    מחבר את שיתוף Windows לתיקיה המקומית.
    vers=3.0 – גרסת SMB (אם נכשל, נסה vers=2.0).

    בדיקת חיבור

    ls /srv/sftp-windows

    בדיקה שהשיתוף מחובר ותכולת Windows מופיעה.

    הוספת CIFS ל-fstab (mount אוטומטי)

    sudo nano /etc/fstab

    הוסף שורה (החלף GID לפי getent group sftpusers): 

    //192.168.130.240/sftp-uploads /srv/sftp-windows cifs credentials=/etc/samba/sftp-credentials,uid=0,gid=1001,file_mode=0770,dir_mode=0770,vers=3.0 0 0

    בדיקת כל ה-mounts מ-fstab

    sudo mount -a

    מחבר את כל ה-mounts שב-fstab שטרם מחוברים. שימושי לבדיקת שורות חדשות שהוספת.

    ניהול משתמשים

    הוספת משתמש עם 2FA

    sudo ~/add-sftp-user.sh client1

    יוצר משתמש SFTP חדש עם chroot, bind mount לשרת Windows, סיסמה, ו-Google Authenticator.

    הוספת משתמש בלי 2FA (סיסמה בלבד)

    sudo ~/add-sftp-user.sh --no-2fa client2

    יוצר משתמש SFTP בלי Google Authenticator – כניסה עם סיסמה בלבד.

    הוספת מפתח SSH ציבורי למשתמש קיים

    sudo ~/add-sftp-public-key.sh client1

    מוסיף מפתח SSH ציבורי לקובץ authorized_keys של המשתמש.

    יצירת מפתח SSH ב-PuTTYgen (בצד הלקוח)

    1. פתח PuTTYgen → Generate
    2. שמור Save private key → קובץ .ppk (ללקוח)
    3. העתק את השורה מהחלון "Public key for pasting into OpenSSH authorized_keys"
    4. הדבק בשרת דרך אפשרות 11 בתפריט

    בדיקת קיום קובץ 2FA

    sudo ls -la /srv/sftp/chroot/client1/.google_authenticator

    בודק שקובץ ה-2FA קיים ובהרשאות הנכונות (-r-------- root root).

    יצירת קובץ 2FA ידנית (אם נדרש)

    sudo bash -c 'cat > /srv/sftp/chroot/client1/.google_authenticator << EOF
SECRET_KEY_HERE
EMERGENCY_CODE_1
EMERGENCY_CODE_2
EMERGENCY_CODE_3
EMERGENCY_CODE_4
EMERGENCY_CODE_5
DISALLOW_REUSE
TOTP_AUTH
EOF'
sudo chown root:root /srv/sftp/chroot/client1/.google_authenticator
sudo chmod 400 /srv/sftp/chroot/client1/.google_authenticator

    יוצר קובץ 2FA ידנית עם מפתח ידוע (במקרה שה-google-authenticator כשל).

    איפוס סיסמה למשתמש

    sudo passwd client1

    מאפס סיסמה למשתמש (מבקש סיסמה חדשה פעמיים).

    תפריט ניהול

    הפעלת התפריט

    menu

    פותח את תפריט ניהול SFTP (alias ל-sudo /opt/sftp-admin/sftp_menu.sh).

    יצירת ה-alias הגלובלי

    sudo tee /usr/local/bin/menu > /dev/null << 'EOF'
#!/bin/bash
exec sudo /opt/sftp-admin/sftp_menu.sh
EOF
sudo chmod +x /usr/local/bin/menu

    יוצר פקודה קצרה menu שזמינה מכל מקום בשרת, לכל משתמש עם sudo.

    אפשרויות התפריט

    מספר פעולה תיאור
    1 Add user הוספת משתמש SFTP חדש
    2 Delete user מחיקת משתמש (כולל/בלי תיקיית Windows)
    3 Disable user נעילת משתמש (בלי מחיקה)
    4 Enable user שחרור נעילת משתמש
    5 Status סטטוס כללי + טבלת כל המשתמשים (CHROOT/WIN_DIR/BIND/FSTAB/2FA/SSH_KEY)
    6 Fix mounts תיקון bind mounts לכל המשתמשים (אחרי אתחול / תקלה)
    7 Inspect user בדיקה מפורטת למשתמש ספציפי
    8 Reset 2FA איפוס Google Authenticator למשתמש
    9 Connected users הצגת משתמשים מחוברים כרגע
    10 Reset password איפוס סיסמה למשתמש
    11 Add/update SSH key הוספה/החלפת מפתח SSH למשתמש
    0 Exit יציאה מהתפריט

    פקודות עזר ותחזוקה

    תיקון שורות Windows (CRLF) בסקריפט

    sed -i 's/\r$//' /opt/sftp-admin/sftp_menu.sh

    מסיר תווי \r (Carriage Return) שנוצרים כשמעתיקים קובץ מ-Windows ללינוקס.
    שגיאה טיפוסית: /usr/bin/env: 'bash\r': No such file or directory
    פתרון: להריץ את הפקודה הזו על הסקריפט הבעייתי.

    תיקון CRLF לכל הסקריפטים בתיקייה

    sed -i 's/\r$//' /opt/sftp-admin/*.sh

    מתקן CRLF בכל הסקריפטים בתיקייה בפעם אחת.

    יצירת alias זמני (לסשן הנוכחי בלבד)

    alias menu='sudo /opt/sftp-admin/sftp_menu.sh'

    יוצר קיצור דרך זמני. נעלם עם סגירת ה-SSH session.

    יצירת alias קבוע (ל-iteam)

    echo "alias menu='sudo /opt/sftp-admin/sftp_menu.sh'" >> ~/.bashrc
source ~/.bashrc

    מוסיף את ה-alias לקובץ .bashrc – יהיה זמין בכל כניסה ב-SSH של המשתמש iteam.

    בדיקת mounts פעילים

    mount | grep cifs
mount | grep bind

    מציג חיבורי CIFS (שיתוף Windows) ו-bind mounts פעילים.

    בדיקת קבוצת sftpusers

    getent group sftpusers

    מציג את כל המשתמשים בקבוצה.

    הצגת GID של הקבוצה

    getent group sftpusers | cut -d: -f3

    מציג רק את המספר (GID) של הקבוצה – נדרש לשורת fstab.

    פקודות אבחון ולוגים

    צפייה בלוג אימות SSH

    sudo tail -30 /var/log/auth.log

    מציג 30 שורות אחרונות מלוג האימות. שימושי לאבחון בעיות כניסה ו-2FA.

    מעקב אחרי לוג בזמן אמת

    sudo tail -f /var/log/auth.log

    מציג את הלוג בזמן אמת (Ctrl+C לעצירה). שימושי כשמנסים להתחבר ורוצים לראות מה קורה.

    הודעות kernel (לאבחון CIFS)

    sudo dmesg | tail -15

    מציג הודעות ליבה – שימושי לאבחון שגיאות mount של CIFS.
    STATUS_LOGON_FAILURE = בעיה ב-credentials (סיסמה/דומיין).

    בדיקת סטטוס שירות SSH

    sudo systemctl status ssh

    מציג אם שירות SSH פעיל, מתי הופעל, ושורות לוג אחרונות.

    בדיקת הגדרות SSH הפעילות

    grep -A 10 "Match Group sftpusers" /etc/ssh/sshd_config

    מציג את כל ההגדרות של קבוצת sftpusers ב-sshd_config.

    בדיקת הגדרות PAM

    grep pam_google_authenticator /etc/pam.d/sshd

    בודק שקיים ה-module של Google Authenticator ב-PAM.

    בדיקת חיבור לשרת Windows

    ping -c 2 fs01

    בודק חיבור רשת לשרת הקבצים.

    בדיקת גרסת Ubuntu

    lsb_release -a

    מציג את גרסת Ubuntu המותקנת.

    חיבור SSH לשרת (מהמחשב)

    ssh -p 2255 iteam@vpn.ms-ci.co.il

    מתחבר לשרת SFTP ב-SSH דרך פורט 2255.

    הגדרות חיבור WinSCP

    שדה ערך
    Protocol SFTP
    Host vpn.ms-ci.co.il (או IP השרת)
    Port 22 (או 2255 אם שונה)
    Username שם המשתמש (client1 וכו')
    Password הסיסמה
    Private key קובץ .ppk שנוצר ב-PuTTYgen
    Verification code קוד 6 ספרות מ-Google Authenticator

    הגדרה חשובה ב-WinSCP לעבודה עם 2FA:
    Advanced → Connection → SSH → Authentication → Allow keyboard-interactive authentication ✓

    הגדרות ב-/etc/ssh/sshd_config (תקציר)

    KbdInteractiveAuthentication yes

Match Group sftpusers
    ChrootDirectory /srv/sftp/chroot/%u
    ForceCommand internal-sftp
    AuthenticationMethods publickey,keyboard-interactive
    AllowTcpForwarding no
    X11Forwarding no
    PermitTTY no

    הגדרות ב-/etc/pam.d/sshd (תקציר)

    @include common-auth
auth required pam_google_authenticator.so nullok
@include common-account
@include common-session
