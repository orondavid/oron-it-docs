    FortiGate SD-WAN – מעבר מ־Load Balancing ל־Failover (Primary / Backup)

    מטרת המדריך

    מדריך זה מסביר שלב־אחר־שלב כיצד להגדיר ב־FortiGate מצב Failover אמיתי (קו ראשי + קו גיבוי), במקום מצב של חלוקת עומסים (Load Balancing) – מבלי לפספס אף הגדרה קריטית, ותוך הבנה מלאה של ההשפעה על המערכת הקיימת.

    הגדרות התחלה (Prerequisites)

    לפני שמבצעים שינוי:

    • ✔ שני קווי האינטרנט פעילים ותקינים
    • ✔ מוגדר SD-WAN
    • ✔ קיים לפחות Health Check אחד פעיל
    • ✔ יש גישת CLI ל־FortiGate

    ⚠️ מומלץ לבצע את השינוי מחוץ לשעות פעילות (ייתכן ניתוק קצר).

    רקע חשוב – מה ההבדל בין Load Balancing ל־Failover

    Load Balancing (המצב הקיים)

    • התעבורה מתחלקת בין שני הקווים
    • יש העדפה ל־WAN1, אך WAN2 עדיין בשימוש
    • אין החלטה חדה מתי קו “נפל”
    • חיבורים ארוכי טווח (RDP / VPN) עלולים ליפול

    Failover אמיתי (המטרה)

    • כל התעבורה יוצאת דרך WAN1
    • WAN2 נכנס לפעולה רק כאשר WAN1 נכשל לפי SLA
    • מעבר חד וברור
    • יציבות גבוהה יותר למשתמשים

    שלב 1 – ביטול חלוקת עומסים (שינוי מצב SD-WAN)

    CLI

    config system sdwan
    set load-balance-mode priority
end

    🔹 פקודה זו מבטלת Load Balancing 🔹 מאפשרת עבודה במצב Primary / Backup בלבד

    שלב 2 – בדיקת Health Check

    בדיקה: 

    diagnose sys sdwan health-check

    ודא: - wan1 = alive - wan2 = alive - latency / packet loss בגבולות שהוגדרו

    ⚠️ ללא Health Check תקין – לא יתבצע Failover

    שלב 3 – הגדרת SD-WAN Rule במצב Priority

    דרך GUI (מומלץ)

    Network → SD-WAN → SD-WAN Rules

    ערוך את ה־Rule הראשי (לדוגמה: Prefer):

    • Source: all
    • Destination: all
    • Strategy / Mode: Priority
    • Interface Order:
    • WAN1 (Primary)
    • WAN2 (Backup)
    • Performance SLA: ✔ בחר Health Check אחד לפחות

    שמור את ההגדרות.

    דרך CLI (חלופה)

    config system sdwan
    config service
        edit 1
            set name "Internet_Failover"
            set src "all"
            set dst "all"
            set priority-members 1 2
            set health-check "Default_Google Search"
        next
    end
end

    שלב 4 – טיפול ב־Implicit SD-WAN Rule

    בדוק ב־GUI: 

    Network → SD-WAN → SD-WAN Rules

    אם קיים Rule בשם: 

    Implicit (sd-wan)
Criteria: Volume

    🔹 מומלץ לנטרל (Disable) אותו 🔹 או לוודא שהוא לא משפיע על תעבורה רגילה

    שלב 5 – בדיקת Firewall Policies (קריטי)

    כל Policy שיוצאת לאינטרנט חייבת להיות מוגדרת כך:

    • Outgoing Interface: SD-WAN

    ❌ אם מוגדר WAN1 או WAN2 ישירות – Failover לא יעבוד

    שלב 6 – NAT

    • אין צורך לשנות הגדרות NAT קיימות
    • NAT על SD-WAN ממשיך לעבוד
    • כתובת המקור מתעדכנת אוטומטית לפי הקו הפעיל

    שלב 7 – בדיקות לאחר ההגדרה

    בדיקה לוגית

    diagnose sys sdwan service

    מצופה: - WAN1 = active - WAN2 = standby

    בדיקת Failover מעשית

    1. ממחשב פנימי: 
      ping 8.8.8.8 -t
    2. נתק פיזית את WAN1
    3. מצופה:
    4. 1–3 packet loss
    5. המשך תעבורה דרך WAN2

    השפעה על מערכת קיימת – מה חשוב לדעת

    מה לא מושפע

    • גלישה רגילה
    • Firewall Policies (אם מוגדרות נכון)
    • NAT
    • חיבורים חדשים

    מה כן משתנה

    • חלוקת עומסים מתבטלת
    • WAN2 ישמש רק כגיבוי
    • חיבורים קיימים (RDP / VPN) ייפלו בזמן מעבר

    ⚠️ זו מגבלה של TCP/IP והאינטרנט – לא של FortiGate

    סיכום

    • שינוי מרכזי אחד: load-balance-mode priority
    • SD-WAN Rule עם Priority + SLA
    • ביטול Implicit Load Balancing
    • אין צורך בשינויים נוספים אם Policies מוגדרות דרך SD-WAN

    ✔ לאחר יישום נכון – מתקבל Failover יציב, ברור וצפוי

    המלצות תפעוליות

    • בצע בדיקת Failover אחת לחודש
    • תעד את ההגדרות
    • אל תחזיר Load Balancing ללא צורך עסקי ברור
